# /forge-extract — 材料实验数据提取与准入

从指定文献或小批来源构建可重放的观测候选。先读 [材料数据接线规范](../../../docs/data-pipeline.md)，从目标、领域 profile、mapping、证据范围和授权确定起点。新领域从 [开库手册](../../../docs/superpowers/new-domain-playbook.md) 起步。已有明确领域配置时直接复用，保留旧版配置与已提交记录的绑定。

## 命令入口

| 参数 | 用法 |
|---|---|
| `/forge-extract` | 选择现有领域配置，或按新领域手册起草 profile 和 mapping。 |
| `/forge-extract --config <name>` | 使用指定配置的版本与范围，先检查本批来源、授权及最近验收。 |
| `/forge-extract --new` | 从新领域定义和首批验证开始。 |
| `/forge-extract --pilot` | 用现有配置做小批试跑，交付门禁结果和回归证据。 |
| `/forge-extract --from extract/papers/` | 跳过检索，以 `raw/extract/papers/` 的指定本地 PDF 为起点。 |
| `/forge-extract --pdf <path>` | 对指定 PDF 建立冻结来源并提取，保留原文件位置。 |
| `--overwrite <id>` | 兼容旧入口。把指定记录纳入修订审计，按现行版本化、暂存和授权规则办理。 |
| `--year-from YYYY` | 设置检索起始年。 |
| `--year-to YYYY` | 设置检索结束年。 |
| `--allow-scihub` | 历史下载参数。下载来源和访问权限按现行流程单独核对。 |

| Skill | 关系 |
|---|---|
| `/forge-discovery` | 发现候选文献及确定来源，随后可将指定来源交给提取流程。 |
| `/forge-ingest` | 将 PDF 摄入 wiki。 |
| `/forge-health` | 检查已登记的数据和知识库健康状态。 |

## 来源、入口与证据

- 冻结 PDF、解析文本、页标记、解析器版本和选项，记录源与文本 SHA-256、文档 ID、snapshot ID。把 `documents`、`parse_snapshots`、`evidence`、`coverage_scopes` 绑定到同一冻结来源。先检查哈希和证据，再读值。
- 现行两级入口按 **表格 > 正文** 工作。表、列、行和单元格都须可追溯。正文用来补缺或旁证。只有样品、条件、事件、性质及单位能对齐时才合并候选，冲突单列。图内取值暂缓，图注文字可以作为可定位证据。图入口解冻及模型读图预算另行批准。
- 以冻结文本的字符区间 `[start,end)` 回放 `quote`。物理页、行号、栏位用于查找与复核。跨行或双栏证据分成同栏连续片段，保留原样切片和先后顺序。省略号只有在原文可定位、可完整展开时才替换成确切证据。无法唯一定位就隔离。
- 按列保留表头单位、原始数值及显式倍率。指数缺号、NUL 或归属不明时保留原字符并标记待复核。任何归一或复算都保留原值、原单位、证据和转换关系。

## Profile、语义与门禁

- 用 profile 声明目标性质、单位与基准、必需上下文、关键字段、可空性和发布规则。mapping 用 JSON Pointer 绑定原始字段。按领域决定记录粒度，明确样品、性质和观测事件，区分实测、名义、作者估计及独立复算。MP 计算性质走独立来源适配。
- 保存约数限定词、数值不确定度及其原文、次数值与 exact/at_least 成对语义、处理链原文、时长限定词和组分依据。只有证据明确时填值。允许缺失的次数对成对留空，按契约记缺失原因。源单位、名义配方、实测组成、时效和热暴露分别绑定。烧蚀 v2 将结果限定词和不确定度放在属性下，Al–Cu 按其领域 profile 落位。
- 按 **prepare → gate → stage → commit → export** 处理。prepare 封装 profile、mapping、原始输入与证据，gate 验证证据、记录及关键字段，stage 保留通过、隔离、排除及回执。commit 按授权和 catalog 哈希重验，export 以明确视图或筛选输出。扫描命中与暂存状态不代表已提交。

## 选择提取路线

| 路线 | 适用条件 | 验收 |
|---|---|---|
| 程序规则模板 | 布局和锚点可唯一确定，字段可从冻结文本重放。 | 逐篇注册布局模板和适用 profile，保留各字段字面锚点，运行重放测试，冻结 rule_hash。暂存前核对来源、规则、profile、mapping 和目标库，独立重放已暂存批次。 |
| 通用 admission | 布局变化、样品归属需人工判读，或规则模板无法唯一匹配。 | 用 prepare_collection_records 或接线规范所列 CLI，按领域门禁验证。需要模型时用已批准的冻结复核周期，结果未通过则隔离。 |

使用 [复核周期用法](../../../docs/review-efficiency.md#review-cycle-用法) 冻结请求，只发送 `pending-requests.json`，`held-requests.json` 保留本地。用 `review-cycle-finish` 合并回答并暂存。调用前核对本批来源哈希、模型、授权和账本额度。批准过的常驻 grant 按既定来源集复用，每批仍用独立授权文件和账本。私有 PDF、笔记及数据库内容保持在本地证据流程内。

## 金标准与协作板

- 先冻结金标准范围、目标定义、定位规则和分母。按表格、正文、布局不确定分别记录精确率、召回率和定位正确率，分列漏检、误报、非目标和重复片段。按 **基线 → 归因 → 修复 → 回归** 保存版本和逐项差异。由扫描候选反向起草的金标准，其召回只可视作本集合上限。真实覆盖率用独立新篇，先人工标注后扫描。
- 协作板按编号追加「主代理指令」「执行报告」「验收」。执行者只追加自己的报告块，记录状态、工件、回归与停点。主代理独立验收。用 [协作协议](../../../docs/agent-collaboration-protocol.md) 的 `batch_check` 在准备、冻结、发送前和区域渲染边界检查适用工件。
- 每个会话处理一篇或一个小批。完成后写交接文件，下一批开启新会话，先运行 `python -B scripts/session_handoff.py check --handoff <路径>`，只读取 `next_command` 所需文件。响应超过 150 次或单次输入超过 150k tokens 时，在下一安全节点交接。摘要输出即可，完整日志留在工件中。

## 授权与停止条件

模型执行、正式 commit 和门禁放宽是独立授权。联网检索与下载按已获授权的范围执行。提交前验证暂存回执、目标库和完整 catalog SHA-256，遇冲突按契约停报。

来源或规则哈希不一致、锚点不唯一、关键条件缺失、证据错配、未授权操作、未知检查失败或已有记录回归时，停在受影响的范围并记录依据。对 `cataloged` 问题按提示修复一次并复查。`uncataloged` 或 `checker_failed` 停报。`conflict` 和 `insufficient` 保留原状态，避免靠重复复核求通过。
