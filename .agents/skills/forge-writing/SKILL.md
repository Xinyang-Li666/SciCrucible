# /forge-writing — 详细工作流

文献锚定型学术写作的完整执行流程。覆盖 Introduction / Methods / Results / Discussion 四段 + Abstract / Conclusion。

> **SciCrucible 根目录**: `D:\科研\SciCrucible\` —— 所有 wiki/、raw/ 路径以此为基准。

---

## 章节路由

`/forge-writing` 根据用户意图自动路由到对应子流程。用户无需记忆命令——自然描述即可：

| 用户说 | 执行 |
|--------|------|
| "写 Introduction" / "写引言" | → Introduction 流程 |
| "写 Methods" / "写实验方法" | → Methods 流程 |
| "写 Results" / "写结果" | → Results 流程 |
| "写 Discussion" / "写讨论" | → Discussion 流程 |
| "写全文" / "完整写" | → Full 模式（M→R→I→D→Abstract→Title） |
| "润色" / "polish" + 提供草稿路径 | → Polish 模式 |
| 无明确章节 | → 默认 Introduction + Discussion（v1 兼容） |

**独立调用 Methods / Results / Abstract / Conclusion 的上下文检查**：

这些子流程不经过阶段 1（三阶深挖），LLM 需要在启动时检查上下文是否充足：

1. 如果用户在**同一会话**中已完成阶段 1 → 使用已有的写作摘要和 KB 上下文
2. 如果用户通过 `--brief <路径>` 提供了写作摘要文件 → 读取并恢复上下文
3. 如果以上均无 → LLM 主动询问：
   > "我没有你的研究上下文（核心发现、材料体系、创新定位）。你可以：
   > (a) 提供一个写作摘要文件路径（`--brief`），
   > (b) 先运行 `/forge-writing intro` 完成阶段 1 深挖后再回来，
   > (c) 或者现在简要告诉我：体系是什么、核心数据是什么、目标期刊是什么。"
4. 如果用户选择 (c) → LLM 做轻量级信息收集（3-5 个问题），不要求完整的 R1-R4

## 阶段 1：写作思路梳理（强制前置）

> **原则**：不跳过、不压缩。用户在确认大纲之前，不生成任何正式段落。适用于 Introduction 和 Discussion（Methods/Results 不需要此阶段）。

### 1.1 理解意图

一次只问一个问题，逐步深入：

**Q1 — 目标期刊**：
"目标期刊是哪种类型？Nature/Science 正刊、子刊、Adv. Mater./ACS Nano 等顶刊、还是中文期刊？"
→ 决定写作深度和风格

**第一阶 · 逐维深挖**（4 轮独立对话，一次只问一个维度，不可合并、不可跳过）

> 每轮 3-4 个追问。等用户完整回答后再进入下一轮。用户卡壳时提供 2-3 个可能方向让其选择。

---

**R1 — 科学问题**（追问到"为什么重要"的根因）

```
🔍 R1：核心科学问题

Q1 | "你研究的核心科学问题是什么？用一句话描述。"

Q2 | "这个问题为什么重要？它阻碍了哪些技术进步或更深层的科学理解？"
     → 追到具体的技术瓶颈或认知空白

Q3 | "如果这个问题被解决了，什么会成为可能？哪些后续研究会因此打开？"

Q4 | "目前这个问题为什么没有被解决？瓶颈是实验技术限制、理论框架缺失、还是材料体系本身的复杂性？"
     → 区分"技术瓶颈"和"认知瓶颈"，这决定了 Introduction P2 的 Gap 陈述方式
```

---

**R2 — 关键发现**（获取定量数据 + 意外发现）

```
🔍 R2：关键发现

Q1 | "你最重要的一个发现或结论是什么？请给出你能分享的最具体的定量数据。"

Q2 | "这个发现中，最让你意外的是什么？有没有反直觉的数据点？"
     → 如果用户说"没有意外"，追问："你的初始假设是什么？实验结果和初始假设完全一致吗？"

Q3 | "这个发现中，哪个数据点/现象是你最确信的（证据最强），哪个是你最不确定的（需要更多验证）？"
     → 区分核心结论和辅助推论

Q4 | "如果只让读者记住一个数据或结论，你希望是什么？"
     → 这是 Discussion P1 的核心素材
```

---

**R3 — 物理机制**（追问因果链 A→B→C，区分"现象描述"和"机制解释"）

```
🔍 R3：物理机制

Q1 | "观察到的现象背后的物理/化学机制是什么？请用 A→B→C 的因果链来描述。
     不只是'X 导致 Y'，而是'X 通过什么中间步骤、在什么能量/动力学驱动下导致 Y'。"
     → 如果用户说"机制还不清楚"，改为："你目前最倾向的假说是什么？"

Q2 | "这个机制的驱动力是什么？是热力学控制、动力学控制、还是两者竞争？"

Q3 | "有没有其他可能的机制解释？你排除了哪些替代假说？基于什么证据排除的？"

Q4 | "这个机制与文献中已有的经典模型有什么本质不同或补充？"
     → 推翻？修正边界条件？填补中间步骤？
```

---

**R4 — 证据链**（了解证据强度和方法基础。**此轮不可跳过**）

```
🔍 R4：证据链与方法基础

Q1 | "支持上述核心发现的证据来自哪些方法？是纯计算、纯实验、还是两者结合？"

Q2 | "最关键的 2-3 个实验/计算结果是什么？这些结果如何支撑你的核心结论？"

Q3 | "证据链中最薄弱的环节是什么？有没有需要额外验证的推论或假设？"
     → 这些成为 Discussion 局限性段落的素材

Q4 | "可以分享的材料体系、关键合成参数、测试条件等 Methods/Results 层面的已知信息有哪些？"
     → 了解体系：成分范围、温度窗口、气氛条件等，指导 KB 文献检索方向
```

**逐维深挖对话规则**：
- **一问一答**：每轮只发一个问题块，等用户回答后再进入下一轮
- **追问必须具体**：不能问"能详细说说吗？"，必须给出具体追问方向
- **用户卡壳时提供选项**：基于已有信息给出 2-3 个可能方向让用户选择
- **如果用户 R1-R4 多轮均为"还没想好"/"暂不清楚"**：暂停并建议用户先完成实验/计算再写作

### 1.2 KB 文献摸底

执行三轮搜索：

**第一轮 — 概念层**：
- 读取 `D:\科研\SciCrucible\wiki\index.md` → 定位相关专题组
- 读取相关概念页（至少 2-3 个）→ 提取领域背景素材和机制解释

**第二轮 — 文献脉络**：
- 读取相关项目页的 §2 文献脉络（期刊评级过滤后的高质量文献演进脉络）
- 读取项目页 §5 核心发现 → 了解当前研究前沿

**第三轮 — 高价值文献**：
- 从 index.md 文献索引中筛选相关文献（优先高评级期刊）
- 读取 3-5 篇最相关的文献页面 → 提取可引用的具体数据和结论

### 1.3 创新锚定（第二阶 + 第三阶）

**第二阶 · 创新矩阵**（LLM 整理，用户确认）

```markdown
## 创新矩阵

| # | 候选创新点 | 类型 | KB 中最近文献 | 与最接近工作的本质差异 | 创新强度 |
|---|-----------|------|-------------|---------------------|---------|
| I1 | <一句话> | 机制/方法/体系/认知 | [[文献A]] (2025) | <本质不同在哪里> | ⭐⭐⭐ 颠覆性 |
| I2 | <一句话> | ... | [[文献B]] (2024) | ... | ⭐⭐ 显著增量 |
| I3 | <一句话> | ... | [[文献C]] (2026) | ... | ⭐ 渐进改进 |
```

用户确认或调整候选创新点后进入第三阶。

**第三阶 · 反向质疑**（LLM 一次性展示 3-5 个挑战问题，用户逐一回应）

```
⚔️ 反向质疑

C1 | 文献挑战: "KB 中 [[文献X]] 已报道类似发现，你的本质区别是什么？"
C2 | 假设脆弱性: "你的结论依赖于什么假设？如果假设不成立呢？"
C3 | 方法论局限: "[某方法] 在 [某体系] 中有已知局限，你如何确保不影响结论？"
C4 | 反例或矛盾: "KB 中 [[文献Y]] 报道了相反结论，怎么理解这个矛盾？"
C5 | 创新性边界: "为什么之前的课题组没有做出来？思路问题/技术门槛/没意识到价值？"
```

用户回应后，LLM 提炼**一句创新陈述**：

```markdown
> **本研究发现/揭示/挑战了 [核心发现]，与 [已有认知] 的本质不同在于 [本质差异]。**
```

**写作语言**：中文

### Introduction 大纲
| 段落 | 核心论点 | 驱动来源 | KB 支撑 |
|------|---------|---------|---------|
| P1 大背景 | UHTC 在 >3000K 氧化环境中的抗烧蚀是航天热防护的瓶颈 | R1 科学问题 + 根因：氧化物层不够致密导致氧持续内扩散 | [[超高温陶瓷氧化机理]] |

| 段落 | 核心论点 | 驱动来源 | KB 支撑 |
|------|---------|---------|---------|
| P1 总结发现 | N 含量 0→0.24 时氧化层从柱状多孔→致密层状，Rd 降低 9× | R2 关键发现 + 创新陈述 | — |
| P2 与 SiC 路线对比 | SiC 自愈合依赖 SiO₂ 流动封填，>2000°C 失效；N 增粘不依赖 SiO₂，适用温度更高 | 创新矩阵 I1（机制层面）+ 第三阶 C1/C4 回应 | Kou2024, Li2025 |

| P4 局限性 | 仅验证了 HfC 基，在 ZrC/TaC 基中是否成立未验证 | R4 薄弱环节 + 第三阶 C2 | [[开放问题]] |

```

## 阶段 2：逐段交互起草

> **原则**：一段一审。先讨论理解再动笔。起草前走通叙事线。每段包含 KB 检索 → 意图对齐 → 起草 → 自检 → 审阅。
> **上下文**：阶段 2 启动前必须先输出写作摘要（见上方），逐段起草时以摘要为索引，按需检索 KB 页面。

...

→ 整体叙事弧线：<概括>
→ 叙事调性：<激进挑战 / 稳健增量 / 填补空白>

```

**Discussion 叙事线走通**（2.0 格式适配）：

好，我理解的叙事线是这样的——

```

### 2.1 KB 深度检索（段级）

对该段核心论点，执行针对性检索：

### 2.2 起草段落

按目标风格起草。如果前一步使用了 argument first 深度模式，直接基于确认的段论点展开；否则正常起草。

#### Nature 英文风格规范

```
- 每段 2-4 句，简洁有力
- 句式：We found that... / In contrast to... / These data indicate...
- 引文：(Author, Year) 放在句末
- 定量：X increased by 35% (from 12.3 ± 1.2 to 16.6 ± 1.4, P < 0.01)
- Introduction 共 3 段，总 ~300 词
- Discussion 共 5 段
- AI 模式禁忌（详见 2.6）：避免 "delve into, shed light on, notably, moreover, furthermore, crucial (滥用), pivotal, paramount, showcase"
```

#### 中文期刊风格规范

```
- 每段 3-6 句，允许适度长句但避免欧化
- 句式：研究表明... / 与...不同... / 这些结果表明...
- 引文：右上角角标 [1-3] 或 (作者, 年)
- 定量：X 从 12.3 ± 1.2 增加到 16.6 ± 1.4，增幅 35%（P < 0.01）
- Introduction 可 5-8 段（综述型引言），总 ~1500 字
- AI 模式禁忌（详见 2.3b）：
  - 避免 "值得注意的是/众所周知/毋庸置疑/综上所述/由此可见/不难发现"
  - 避免 "具有重要意义/引起了广泛关注/提供了新的思路"
```

## Introduction P2：文献→Gap（草稿）

SiC 和 MoSi₂ 等含硅添加剂通过氧化生成流动性 SiO₂ 封填裂纹和孔隙，在 1600-2000°C 范围内将 HfC/ZrC 基 UHTC 的线烧蚀率降低了 50-80% [1-3]。然而，SiO₂ 在 >2000°C 时蒸气压急剧升高，封填效果迅速退化——Kou2024 报道 C/C-HfC-SiC 在 2200°C 氧乙炔烧蚀 120s 后 Rd=0.77 mg/s，与不含 SiC 的体系相比改善有限 [4]。这一温度上限意味着现有自愈合策略在 2500-3500K 的最极端热环境中几乎失效。

近年有课题组尝试将氮引入 HfC 晶格，初步结果显示 HfC₀.₇₆N₀.₂₄ 在 3273K 的 Rd 仅为纯 HfC 的 1/9 [5]，但这一异常改善的机制未被阐明——Peng2025 将其归因于氮的"物理阻挡"作用，但物理阻挡无法解释为何仅 24% 的 N 取代就能产生 9× 的改善。目前，N 掺杂对氧化物熔体化学状态（聚合度、氧扩散系数）的影响尚缺乏系统研究。

### 来源追溯
| 论断 | KB 来源 | 期刊评级 | 支撑强度 |
|------|---------|---------|---------|
| "SiC 在 1600-2000°C 将 Rd 降低 50-80%" | [[Li2025]], [[Kou2024]] | 评级2, 评级1 | ★★★ |
| "SiO₂>2000°C 蒸气压升高致封填退化" | [[超高温陶瓷氧化机理]] | — | ★★☆ |
| "HfC₀.₇₆N₀.₂₄ 的 Rd 为纯 HfC 的 1/9" | [[Peng博士]] | 博士论文 | ★★★ |
| "物理阻挡无法解释 9× 改善" | 本文分析 | — | [待验证] |

### 辩证自检

**替代解释**：N 的改善可能来自 (a) 化学增粘 (b) 物理阻挡 (c) N₂ 气体发汗冷却——Peng 倾向于 (b)，我们倾向于 (a)。
**KB 支撑评估**：SiC 退化有 2 篇文献直接支撑；N 增粘/物理阻挡之争的区分尚无直接 KB 支撑——这是本工作的 Gap 定位。
**矛盾或张力**：Peng2025 的物理阻挡解释与我们的 9× 定量数据不矛盾，但"机制归因"存在分歧——这是本工作的切入点而非矛盾。
**意图一致性**：实现了锚点确认的核心论点——"已有自愈合策略在 >2000°C 失效 + N 掺杂的机制未被区分"。

## 子流程：Introduction

Introduction 使用标准阶段 2 流程（2.0-2.6），结构模型：

```
P1 | 大背景（从具体场景/数据切入，不是泛泛说"很重要"）
P2 | 文献→Gap（已有方案及其局限 → 关键 Gap 的定性）
P3 | 我们的方案（核心发现 + 与已有工作的本质不同）
```

**叙事线走通**（2.0）为 Introduction 必须执行的步骤。
**段落锚点确认**（2.1.5）中 P2（Gap 段）永不跳过。

## 子流程：Discussion

Discussion 使用标准阶段 2 流程（2.0-2.6），结构模型：

```
P1 | 核心发现总结（不重复 Results，提炼 1-2 个最重要的信号）
P2 | 与最接近工作的本质差异（不仅是"更好"，而是"为什么更好"）
P3 | 机制深入（因果链 A→B→C，驱动力，排除的替代假说）
P4 | 局限性 & 未解决的问题（诚实而非自我贬低）
P5 | 展望 & 意义（如果成立，什么会成为可能？下一步往哪走？）
```

**Discussion 独有自检项**（2.3 追加）：

```
**与 Results 一致性检查**：
- 本段讨论的发现是否全部在 Results 中有数据支撑？
- 是否有 Results 中的重要数据在 Discussion 中没有被讨论？

**Claim 校准**：
- 每个 claim 的动词强度是否匹配证据强度？

```

Move 4 | 数据中的趋势/模式（1-2 句，不做机制解释）
Move 5 | 与对照组的比较（1-2 句，定量）
Move 6 | 本段 takeaway（1 句——仍不做机制解释，只做信号总结）
```

写作原则：
- 以"我们发现…"开头，不以"图 X 显示了…"开头
- 过去时描述发现，现在时描述图表
- 数值必须有误差范围
- 每段 1 个核心信息
- **不在 Results 中做机制解释**（那是 Discussion 的工作）
- **不在 Results 中引用文献做对比**（那是 Discussion 的工作）

### R.4 数据准确性自检

```
| # | 检查项 | 状态 |
|---|--------|------|
| 1 | 所有数值与用户提供的数据一致 | ✅ |
| 2 | 所有数值附带了误差范围 | ✅ / ⚠️ |
| 3 | 没有在 Results 中做机制解释 | ✅ / ❌ |
| 4 | 没有在 Results 中引用文献做对比 | ✅ / ❌ |
| 5 | 每段的 takeaway 与全局创新陈述一致 | ✅ / ⚠️ |
| 6 | 正文没有重复表格/图中已有的全部数据 | ✅ / ❌ |
| 7 | 所有图表在正文中至少被引用一次 | ✅ / ❌ |
```

### R.5 展示审阅

同标准 2.4 格式，追加来源追溯和辩证自检。

## 子流程：Abstract

> 最后写。5 段漏斗结构（借鉴 nature-writing）。

```
P1 | 大背景（1-2 句）：<领域> + <为什么重要>
P2 | 具体问题（1 句）：<Gap> — "hinge" 句
P3 | 核心结果（1-2 句）："Here we show..." + 定量数据
P4 | 机制/意义（1-2 句）：<为什么是这个结果> + <对领域的含义>
P5 | 边界/展望（1 句，可选）
```

总 ~150-250 词（Nature）或 ~300-500 字（中文）。

**Abstract 自检**：

```
| # | 检查项 | 状态 |
|---|--------|------|
| 1 | 每个数字与 Results 正文完全一致 | ✅ / ❌ |
| 2 | 没有出现正文未出现的结论 | ✅ / ❌ |
| 3 | 没有引用文献（Nature summary paragraph 除外） | ✅ / ❌ |
| 4 | 总词数在目标范围内（Nature ~150-250 词，中文 ~300-500 字） | ✅ / ⚠️ |
| 5 | P3 "Here we show..." 句包含了最重要的定量数据 | ✅ / ❌ |
| 6 | P2 "hinge" 句明确指出了 Gap/未解决的问题 | ✅ / ❌ |
| 7 | 独立可读——不依赖正文即可理解论文的核心贡献 | ✅ / ❌ |
```

---

## 子流程：Conclusion

> 最后写。与 Abstract 互补而非重复。

```
P1 | 核心贡献（1-2 句）：本文做了什么、发现了什么
P2 | 最重要的定量结论（1-2 句）
P3 | 机制解释（1-2 句）：为什么
P4 | 意义/展望（1-2 句）：意味着什么、下一步
```

与 Abstract 的区别：
- Abstract 面向"这篇论文讲什么"（独立可读）
- Conclusion 面向"这篇论文意味着什么"（读者已读完正文）
- Conclusion 可引用少量关键文献做对比
- Conclusion 可更明确地指出局限性和后续方向

**Conclusion 自检**：

```
| # | 检查项 | 状态 |
|---|--------|------|
| 1 | P1 核心贡献与 Abstract P3 不重复（角度不同：Abstract 说"做了什么"，Conclusion 说"贡献了什么"） | ✅ / ⚠️ |
| 2 | P2 定量结论与 Results 正文一致 | ✅ / ❌ |
| 3 | P3 机制解释与 Discussion P3 一致但更精炼（不引入新机制） | ✅ / ❌ |
| 4 | P4 展望与 Discussion P5 一致但可以从更宏观的角度写 | ✅ / ⚠️ |
| 5 | 没有引入正文未出现的新数据或新结论 | ✅ / ❌ |
| 6 | 没有简单地逐句复述 Abstract | ✅ / ❌ |
```

## Polish 模式

触发：`/forge-writing polish <草稿路径>` 或 `/forge-writing 润色 <路径>`

```
Polish 流程

1. 读取用户提供的草稿文件
2. 读取风格校准档案（如有）
3. 逐段执行：
   a. 语言层自检（中文 2.3b / 英文 2.6 + 中→英陷阱）
   b. 风格校准润色（如有档案）
   c. 展示 原文 → 修改 → 原因 三栏对比
4. 综合审校（同阶段 3 但跳过逻辑一致性——保持原文结构不变）
```

**Polish 不改动**：段落结构、引文、数据、作者宣称强度。
**Polish 只改**：AI 模式虚词（L1 自动）、句式节奏（L2 建议）、风格对齐（L3）。

**示例——Polish 三栏对比**（一段的润色结果）：

## Full 模式编排

当用户调用 `/forge-writing full` 或请求完整论文写作时，按以下顺序执行：

```
阶段 1（前置·共享）: 三阶深挖（R1-R4） → KB 摸底 → 创新锚定 → 大纲
    ↓
Methods  →  先写（数据最具体，不需要文献定位）
    ↓
Results  →  基于 Methods 的实验链展示数据
    ↓
Introduction → 基于 Results 的核心发现反向定位文献中的创新位置
    ↓
Discussion → 将发现与文献进行深度对话
    ↓
Abstract → 总结全貌（5 段漏斗）
    ↓
Conclusion → 意义与展望
    ↓
Title → 最后写
```

**两轮制执行细则**：

**第一轮** — M→R→I→D 依次起草：
- Methods 和 Results 写完后，核心数据和实验条件已固定
- Introduction 基于 **实际写出的 Results**（而非阶段 1 的预期）反向定位文献中的位置
- Discussion 基于 **实际写出的 Results + Introduction 定位** 展开

**第二轮** — I→D 回修：
- 重读 Methods + Results 的最终版本
- Introduction 检查：阶段 1 预期 vs 实际 Results 是否一致？
  - 如果不一致（如预期 Rd=0.0005 但实际最优是 0.002）→ 调整 Introduction 的 Gap 定位和承诺强度
  - 如果 Introduction P3 "我们的方案"与实际 Methods 有出入 → 修正
- Discussion 检查：
  - P2 对比对象是否基于实际 Results 数据选择了最合适的文献？
  - P3 机制讨论是否与 Results 中的机制证据严格对应？
  - P4 局限性是否反映了实际写作中发现的薄弱环节？
- 修订时不重写整段——只修正不一致之处

**第二轮完成后** → 继续 Abstract → Conclusion → Title

## 阶段 3：综合审校

所有段落完成后执行。

### 3.1 逻辑一致性检查

```
- 段落间过渡是否自然？
- Introduction P3 的方案是否与 Discussion P1 的发现总结一致？
- Discussion 中提到的机制是否在 Introduction P2 的文献综述中有铺垫？
- Abstract 中的每个数字是否与 Results 正文一致？
- Abstract 中是否出现了正文没有的结论？

```

## 边界条件

- **如果用户在第一阶 R1-R4 多轮回答中均为"还没想好"/"暂不清楚"**：暂停流程，不建议基于模糊信息继续起草
- **如果知识库中无相关文献**：明确告知，建议先 `/forge-discovery` 检索 + `/forge-ingest` 补充
- **如果用户跳过阶段 1 直接要求起草**：拒绝并引导回阶段 1（Methods/Results 除外，不需要阶段 1）
- **如果一段中 KB 支撑率 < 30%**：暂停，提示该段缺乏文献基础
- **绝不编造数据、文献或结论**——所有内容必须可追溯到 KB 页面或用户提供的数据
- **引文格式中期刊评级标注仅用于内部追溯表**，不写入正式段落
- **中文和英文不能混在同一段落中**
- **不主动读取 KB 文件**：如需额外 KB 内容，提示用户并等待确认
- **用户可能只想润色已有草稿**：使用 Polish 模式，不改动结构
- **写作中发现 KB 缺口**：自动记录到"待摄入清单"，写作完成后提醒用户
