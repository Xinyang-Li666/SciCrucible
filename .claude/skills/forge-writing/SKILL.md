# /forge-writing — 详细工作流

文献锚定型学术写作的完整执行流程。

## 输入

用户通过 `/forge-writing` 或触发短语提出写作需求，提供：

- 选题 / 论文标题
- 目标章节（Introduction / Discussion / 两者）
- 目标期刊（决定风格和深度）
- 已有的实验/计算数据要点（Methods/Results 层面的已知信息）

## 阶段 1：写作思路梳理（强制前置）

> **原则**：不跳过、不压缩。用户在确认大纲之前，不生成任何正式段落。

### 1.1 理解意图

一次只问一个问题，逐步深入：

**Q1 — 目标期刊**：
"目标期刊是哪种类型？Nature/Science 正刊、子刊（Nature Energy/Materials）、Adv. Mater./ACS Nano 等顶刊、还是中文期刊（无机材料学报/硅酸盐学报）？"
→ 决定写作深度和风格

**第一阶 · 逐维深挖**（4 轮独立对话，一次只问一个维度，不可合并、不可跳过）

> 每轮 3-4 个追问。等用户完整回答后再进入下一轮。用户卡壳时提供 2-3 个可能方向让其选择，而不是放弃追问。

---

**R1 — 科学问题**（追问到"为什么重要"的根因）

```
🔍 R1：核心科学问题

Q1 | "你研究的核心科学问题是什么？用一句话描述。"

Q2 | "这个问题为什么重要？它阻碍了哪些技术进步或更深层的科学理解？"
     → 追到具体的技术瓶颈或认知空白，不能停留在"这是一个热点方向"

Q3 | "如果这个问题被解决了，什么会成为可能？哪些后续研究会因此打开？"
     → 评估问题的杠杆效应——解决它之后领域格局会改变什么

Q4 | "目前这个问题为什么没有被解决？瓶颈到底是什么——是实验技术限制、
     理论框架缺失、还是材料体系本身的复杂性？"
     → 区分"技术瓶颈"和"认知瓶颈"，这决定了 Introduction P2 的 Gap 陈述方式
```

R1 结束时 LLM 内化：
- 用户研究要回答的科学问题（1 句）
- 该问题的根因重要性（技术瓶颈 or 认知空白）
- 解决后的领域影响
- 未解决的根本原因 → Introduction P2 的 Gap 核心

---

**R2 — 关键发现**（获取定量数据 + 意外发现）

```
🔍 R2：关键发现

Q1 | "你最重要的一个发现或结论是什么？请给出你能分享的最具体的定量数据。"
     → 必须有数值或至少有大致的量级/趋势

Q2 | "这个发现中，最让你意外的是什么？有没有反直觉的数据点？"
     → 意外发现往往是创新点的种子。如果用户说"没有意外"，追问：
       "你的初始假设是什么？实验结果和初始假设完全一致吗？"

Q3 | "这个发现中，哪个数据点/现象是你最确信的（证据最强），
     哪个是你最不确定的（需要更多验证）？"
     → 区分核心结论和辅助推论，决定写作时哪些可以大胆写、哪些要加 caveat

Q4 | "如果只让读者记住一个数据或结论，你希望是什么？"
     → 这是 Discussion P1 的核心素材
```

R2 结束时 LLM 内化：
- 最核心的定量发现（含数值/趋势/量级）
- 反直觉或意外的数据点
- 证据强弱分级
- "一句话记忆点"

---

**R3 — 物理机制**（追问因果链 A→B→C，区分"现象描述"和"机制解释"）

```
🔍 R3：物理机制

Q1 | "观察到的现象背后的物理/化学机制是什么？请用 A→B→C 的因果链来描述。
     不只是'X 导致 Y'，而是'X 通过什么中间步骤、在什么能量/动力学驱动下导致 Y'。"
     → 如果用户说"机制还不清楚"，改为："你目前最倾向的假说是什么？"

Q2 | "这个机制的驱动力是什么？是热力学控制（相稳定性、形成能）、
     动力学控制（扩散、形核势垒）、还是两者竞争？"
     → 将机制锚定到具体的物理化学框架中

Q3 | "有没有其他可能的机制解释？你排除了哪些替代假说？基于什么证据排除的？"
     → 这是 Discussion 中最有说服力的部分——"我们考虑过 X 可能性但排除了，因为 Y"

Q4 | "这个机制与文献中已有的经典模型有什么本质不同或补充？"
     → 建立与已有知识的关系——推翻？修正边界条件？填补中间步骤？
```

R3 结束时 LLM 内化：
- A→B→C 因果链（含驱动力）
- 排除了哪些替代假说 + 排除依据
- 与已有模型的关系（推翻/修正/填补）

---

**R4 — 证据链**（了解证据强度和方法基础。**此轮不可跳过**）

```
🔍 R4：证据链与方法基础

Q1 | "支持上述核心发现的证据来自哪些方法？是纯计算、纯实验、还是两者结合？"
     → 如果未完成："你计划用哪些方法？目前的 preliminary data 有什么？"

Q2 | "最关键的 2-3 个实验/计算结果是什么？这些结果如何支撑你的核心结论？"
     → 每个结果 → 对应支撑哪个发现（R2）+ 哪个机制（R3）

Q3 | "证据链中最薄弱的环节是什么？有没有需要额外验证的推论或假设？"
     → 这些成为 Discussion 局限性段落的素材

Q4 | "可以分享的材料体系、关键合成参数、测试条件等 Methods/Results 层面的已知信息有哪些？"
     → 了解体系：成分范围、温度窗口、气氛条件等，指导 KB 文献检索的精准度
```

R4 结束时 LLM 内化：
- 方法体系（计算/实验/结合）+ 关键参数
- 支撑每个发现的证据强度（强/中/需验证）
- 薄弱环节清单 → Discussion 局限性素材
- 材料体系信息 → 指导下一阶段 KB 文献检索方向

---

**逐维深挖对话规则**：
- **一问一答**：每轮只发一个问题块，等用户回答后再进入下一轮
- **追问必须具体**：不能问"能详细说说吗？"，必须给出具体追问方向
- **用户卡壳时提供选项**：基于已有信息给出 2-3 个可能方向让用户选择
- **如果用户 R1-R4 多轮均为"还没想好"/"暂不清楚"**：暂停并建议用户先完成实验/计算再写作，不基于模糊信息继续

### 1.2 KB 文献摸底

执行三轮搜索：

**第一轮 — 概念层**：

- 读取 `wiki/index.md` → 定位相关专题组
- 读取相关概念页（至少 2-3 个）→ 提取领域背景素材和机制解释

**第二轮 — 文献脉络**：

- 读取相关项目页的 §2 文献脉络（期刊评级过滤后的高质量文献演进脉络）
- 读取项目页 §5 核心发现 → 了解当前研究前沿

**第三轮 — 高价值文献**：

- 从 index.md 文献索引中筛选相关文献（优先高评级期刊：评级1、顶级期刊）
- 读取 3-5 篇最相关的文献页面 → 提取可引用的具体数据和结论

### 1.3 创新锚定（第二阶 + 第三阶）

> 原则：基于第一阶深挖（R1-R4）和 1.2 KB 文献摸底，LLM 整理创新矩阵，用户确认后进入反向质疑辩论，最终产出一句创新陈述。

---

**第二阶 · 创新矩阵**（LLM 整理，用户确认）

LLM 基于第一阶深挖内化结果 + KB 文献调研，整理创新矩阵并展示给用户：

```markdown
## 创新矩阵

基于我们的讨论和 KB 文献调研，以下是候选创新点：

| # | 候选创新点 | 类型 | KB 中最近文献 | 与最接近工作的本质差异 | 文献支撑 | 创新强度 |
|---|-----------|------|-------------|---------------------|---------|---------|
| I1 | <一句话> | 机制 | [[文献A]] (2025) | <本质不同在哪里> | ★★☆ | ⭐⭐⭐ 颠覆性 |
| I2 | <一句话> | 方法 | [[文献B]] (2024) | <本质不同在哪里> | ★★★ | ⭐⭐ 显著增量 |
| I3 | <一句话> | 体系 | [[文献C]] (2026) | <本质不同在哪里> | ★☆☆ | ⭐ 渐进改进 |

### 类型说明
- **机制创新**：揭示了新的因果链或修正了已有模型
- **方法创新**：新的合成/表征/计算方法或跨领域方法迁移
- **体系创新**：将已知机制应用于全新材料体系
- **认知创新**：推翻或修正了领域内的已有认知

### 创新强度说明
- ⭐⭐⭐ 颠覆性：如果成立，领域内已有认知需要被修正
- ⭐⭐ 显著增量：在已有框架内推进了显著一步
- ⭐ 渐进改进：优化了已有体系/方法的某个方面

### 建议核心锚点
> 建议将 **I1** 作为本文的核心创新锚点，**I2** 作为辅助创新点。
> Introduction 叙事主线：从 [已有认知] → 但 [Gap/矛盾] → 我们通过 [I1] 发现 [核心结论]。
```

交互：用户确认或调整候选创新点（"I1 定位偏高""I2 才是核心""I3 已有课题组在做"），LLM 根据反馈修正矩阵，最终确定 1-2 个核心创新锚点。

---

**第三阶 · 反向质疑**（LLM 主动挑战，用户在辩论中精炼创新定位）

用户确认创新矩阵后，LLM 基于 KB 文献提出 3-5 个具体挑战问题。形式为**一次性全部展示**（不逐条问答），用户逐一回应。

```
⚔️ 反向质疑

基于 KB 文献脉络和你提供的研究细节，以下是我的疑问：

C1 | 文献挑战
    "KB 中 [[文献X]] (2025, 评级1/顶级) 已经在 [体系] 中报道了类似的 [机制/现象]，
    他们给出的解释是 [他们的解释]。
    你的工作与他们的本质区别是什么？如果审稿人拿这篇来质疑你，你如何回应？"

C2 | 假设脆弱性
    "你的核心结论依赖于 [某个假设/条件]。
    如果 [假设不成立 or 条件改变]，结论是否仍然成立？
    你有没有在 [其他条件] 下验证过？"

C3 | 方法论局限
    "[某个方法] 在 [特定体系] 中有已知的局限性——[具体局限]。
    你如何确保这个局限性没有影响你的结论？"

C4 | 反例或矛盾
    "KB 中 [[文献Y]] 报道了与你相反的结论——他们发现 [相反结论]。
    你怎么理解这个矛盾？是体系差异、方法差异、还是其中一个结论需要修正？"

C5 | 创新性边界
    "如果你的主要创新是 [创新点]，为什么之前的课题组没有做出来？
    是因为思路问题（没人想到）、技术门槛（想到了做不到）、
    还是因为之前被认为不重要（做到了但没意识到价值）？"
```

用户逐一回应挑战后，LLM 提炼一句**创新陈述（Innovation Statement）**：

```markdown
## 创新陈述

> **This work [reveals/challenges/demonstrates] that [核心发现],
> which is fundamentally different from [已有认知] because [本质差异].**

或中文版：
> **本研究发现/揭示/挑战了 [核心发现]，
> 与 [已有认知] 的本质不同在于 [本质差异]。**
```

**这一句话将成为 Introduction 和 Discussion 的叙事锚点。** 用户确认创新陈述后，进入大纲阶段。

---

### 1.4 提出大纲

以结构化表格展示。大纲各段落直接由三阶深挖的产出驱动：

```markdown
## 拟定大纲

**目标期刊**：<期刊名>
**写作语言**：中文 / English
**创新陈述**：<第三阶产出的一句话>

### Introduction 大纲

| 段落 | 核心论点 | 驱动来源 | KB 支撑 |
|------|---------|---------|---------|
| P1 大背景 | <一句话> | R1 科学问题 + 根因重要性 | [[概念页]] |
| P2 文献→Gap | <一句话> | R1 未解决原因 + 创新矩阵（已有文献列） | [[项目脉络]] + N 篇文献 |
| P3 我们的方案 | <一句话> | 创新陈述 + R2 一句话记忆点 | 用户数据 + [[概念页]] |

### Discussion 大纲

| 段落 | 核心论点 | 驱动来源 | KB 支撑 |
|------|---------|---------|---------|
| P1 总结发现 | <一句话> | R2 关键发现 + 创新陈述 | — |
| P2-3 文献对比+机制 | <一句话> | 创新矩阵（本质差异）+ 第三阶挑战回应 | [[概念页]] + N 篇文献 |
| P4 局限性 | <一句话> | R4 薄弱环节 + 第三阶假设脆弱性 | [[开放问题]] |
| P5 展望 | <一句话> | R1 解决后的领域影响 | [[跨领域关联]] |

**支撑强度说明**：
- ★★★ 强：KB 中有充分的概念定义 + ≥3 篇高评级期刊文献支撑
- ★★☆ 中：KB 中有相关概念但文献数量不足或评级偏低
- ★☆☆ 弱/需补充：KB 覆盖薄弱，写作前建议补充文献或标注 [待验证]
```

### 1.5 识别盲区

```markdown
## KB 覆盖盲区

以下方向的知识库覆盖薄弱，可能影响写作质量：

1. **[具体空白方向]** — KB 中仅有 X 篇相关文献（均为 Y 区），建议摄入 1-2 篇该方向顶刊文献
2. **[无覆盖的方向]** — KB 中无直接相关内容，该段将标注 [待验证]
3. **[创新矩阵中文献支撑薄弱的方向]** — Ix 的文献支撑仅 ★☆☆，建议补充检索

建议操作：
- `/forge-discovery` 检索以下方向：<基于盲区的搜索词>
- `/forge-ingest` 补充以下文献：<建议列表>
- 或：写作时该部分标注 [待验证]，由用户手动补充
```

### 1.6 等待确认

展示大纲后，明确提问：

> "以上大纲是否符合你的预期？是否需要调整段落结构或核心论点？确认后进入逐段起草。"

**绝不跳过此步骤。**

---

## 上下文管理策略

> **原则**：三阶深挖 + KB 摸底 + 创新锚定会产生大量对话历史。在进入实际写作前必须压缩上下文。

### 阶段 1.6 确认后，强制输出结构化写作摘要

用户确认大纲后，LLM 必须在进入阶段 2 之前输出以下压缩摘要（< 2000 字）：

```markdown
## 写作摘要（供阶段 2 使用）

### 创新陈述
<一句创新陈述，来自第三阶>

### 核心数据点
- R2 定量发现: <数值/趋势>
- R2 一句话记忆点: <...>
- R3 A→B→C 因果链: <...>

### Introduction 叙事线
P1: <大背景一句话>
P2: <Gap一句话>  
P3: <我们的方案一句话>

### Discussion 关键论点
P1: <核心发现总结>
P2-3: <与文献的本质差异>
P4: <局限性要点>
P5: <展望要点>

### KB 支撑速查
- 最关键的 5 篇引用文献: [[A]], [[B]], [[C]], [[D]], [[E]]
- 最相关的 2 个概念页: [[X]], [[Y]]
```

### 逐段起草时的上下文使用规则

- 每个段落起草时，LLM 首先读取上述摘要，然后**只读取该段落在摘要中标注的 KB 来源**（而非重新遍历全部文献）
- 如果某个论断需要额外的 KB 支撑（摘要中未覆盖），再执行针对性检索
- 每完成一个段落，将段落的"来源追溯"追加到摘要中，逐步增量

### 如果上下文已接近极限

- 优先保留：创新陈述 + 核心数据点 + KB支撑速查
- 可丢弃：R1-R4 原始问答（已内化为摘要）
- 可丢弃：第三阶挑战的具体措辞（已内化为创新陈述）

---

## 阶段 2：逐段交互起草

> **原则**：一段一审。每段包含 KB 检索 → 起草 → 辩证自检 → 展示 → 用户反馈 → 修订 → 确认。
> **上下文**：阶段 2 启动前必须先输出写作摘要（见上方策略），逐段起草时以摘要为索引，按需检索 KB 页面。

### 2.1 KB 深度检索（段级）

对该段核心论点，执行针对性检索：

- 如果该段涉及机制解释 → 精读相关概念页的对应 `###` 子标题段落
- 如果该段需要引文 → 读取具体文献页的"关键发现"和"方法"段
- 如果需要定量数据 → 从文献页和有数据的 wiki 页提取具体数值

### 2.2 起草段落

按目标风格起草：

#### Nature 英文风格规范

```
- 每段 2-4 句，简洁有力
- 句式：We found that... / In contrast to... / These data indicate...
- 引文：(Author, Year) 放在句末
- 定量：X increased by 35% (from 12.3 ± 1.2 to 16.6 ± 1.4, P < 0.01)
- Introduction 共 3 段，总 ~300 词
- Discussion 共 5 段
```

#### 中文期刊风格规范

```
- 每段 3-6 句，允许适度长句但避免欧化（"的...的...的..."嵌套）
- 句式：研究表明... / 与...不同... / 这些结果表明...
- 引文：右上角角标 [1-3] 或 (作者, 年)，放在句末
- 定量：X 从 12.3 ± 1.2 增加到 16.6 ± 1.4，增幅 35%（P < 0.01）
- Introduction 可扩展到 5-8 段（综述型引言），总 ~1500 字
- Discussion 可 5-7 段
- 中文特有禁忌：
  - 避免 "本文研究了..."（改为 "本研究围绕..."）
  - 避免 "国内外研究现状" 这样的空泛标题
  - 避免大段罗列文献而无逻辑串联
  - 避免长串英文缩写不解释（首次出现必须给出全称）
```

#### 引文格式映射

生成的段落中，文献引用以 KB 双链 `[[文献页名]]` 标记，同时转换为目标期刊格式：


| KB 标记                  | Nature 英文               | 中文期刊 |
| ---------------------- | ----------------------- | ---- |
| `[[Liu2025-氧框架稳定性Mo]]` | (Liu et al., 2025)      | [1]  |
| `[[掺杂策略与设计原理]]`        | 不直接引用概念页（改为引用概念页中的具体文献） |      |


**规则**：概念页不直接作为引文出现，必须穿透到概念页中引用的具体文献。

## 边界条件

- **如果用户在第一阶 R1-R4 多轮回答中均为"还没想好"/"暂不清楚"/"数据还没出来"**，暂停流程，明确告知用户："目前的研究细节不足以支撑有针对性的写作。建议先完成关键实验/计算，得出至少一个核心发现后，再来写作。强行基于模糊信息起草会导致 Introduction 空洞无锚点。"——**不基于模糊信息继续起草**
- 如果知识库中无相关文献（KB 为空或方向不匹配），明确告知用户，建议先 `/forge-discovery` 检索 + `/forge-ingest` 补充文献
- 如果用户跳过大纲阶段直接要求起草，拒绝并引导回阶段 1
- **如果用户跳过第一阶逐维深挖（R1-R4）直接要求进入大纲**，拒绝并引导回阶段 1.1。不可用一句粗略描述替代四轮深挖
- 如果一段中 KB 支撑率 < 30%，暂停写作，提示用户该段缺乏文献基础
- 绝不编造数据、文献或结论——所有内容必须可追溯到 KB 页面或用户提供的数据
- 引文格式中期刊评级标注仅用于内部追溯表，不写入正式段落（除非用户要求）
- 中文和英文不能混在同一段落中——要么全文中文、要么全文英文
