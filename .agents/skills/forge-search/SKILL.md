# /forge-search — 知识查询

> **SciCrucible 根目录**: `D:\科研\SciCrucible\` —— wiki/ 以此为基准。

用自然语言查询知识库，返回综合分析答案。

## 按需检索（普通科研讨论也适用）

- 用户的问题涉及本项目研究对象、实验指标、方法或已有结论时，默认执行本地轻量探测；用户无需显式写 `/forge-search`。翻译、润色等纯文字任务不探测。用户明确要求查库时必须检索。
- 新一轮科研讨论运行 `python scripts/evidence_query.py probe --query "<用户问题>"`；命令在本地刷新目录指纹后查找，能发现新增/变化文件。探测只返回最多 5 条、合计不超过 1600 字符的候选；仅对相关候选定向读取。
- 读取 wiki 候选后沿相关双链扩展；读取 database 候选时必须筛选材料/测试条件和所需字段，例如 `python scripts/evidence_query.py expand --source-id <ID> --columns id material.label test.method test.duration_s test.results.linear_loss_rate.value --where '{"material.label":"HfC"}' --limit 10`。
- 在同一连续讨论中，已读取证据仍在上下文且来源未变时复用；问题新增对象、指标、条件或证据不足时重新探测。明确区分“本地未找到”和“该领域没有证据”。
- 脚本报错、目录过期或 JSON 损坏时如实报告，不将错误解释为无匹配。不得把本地全文或私有数据库上传给外部检索插件。

## 入口与失败回退（试点修正）

- 优先照抄候选的 `read_args`（参数数组，接在 `python scripts/evidence_query.py` 后），不要猜 `source_id`。数据库可用重复的 `--record-id <记录ID>` 选多条记录，再用 `--columns` 选字段；无需拼 JSON。`--where` 只接受精确匹配的 JSON 对象，不接受 SQL。数据库禁止无条件展开；检查 `matched_records`、`returned_records`、`truncated` 和 `truncation_reason`，截断不等于后面没有记录。
- 同名技能以本项目 `.agents/skills/` 下版本为准，不使用用户目录中的旧版同名技能替代；普通科研讨论也遵守项目 AGENTS.md。
- `probe` 已刷新目录，无需每次额外 `build`。明确查库的任务必须完成实际探测/读取后再回答，不能只回复“准备查询”。优先使用用户给出的完整记录 ID 或样品代号；不要读取脚本源码来猜数据层级。
- `status:error` 是读取/工具失败，不是无匹配。空候选只表示本次查找未命中；对明确本地对象可再用短关键词/准确 ID 查找一次。仍需后备搜索时用 `rg --no-ignore -n "<短关键词或ID>" wiki database`，严格限制在这两个允许根内，不从工作区根目录搜索，避免漏掉被 Git 忽略的数据库或读到评测参考。
- 相关候选出现后再定向读取；数据库用 `expand` 选择记录和字段。连续追问先复用已读原始证据；首轮尚未取到证据时不能把前次表态或“未找到”当证据复用。

## 流程

1. **轻量探测**：针对研究问题运行本地 `probe`，不将全局索引或数据库整体读入上下文
2. **定位入口**：读取相关候选；必要时沿 `[[wiki-link]]` 定向扩展
3. **按需查数据**：问题涉及实验表现时，通过 database 记录筛选所需材料、条件和指标
4. **综合回答**：区分库内证据、一般知识和推断
5. **标注来源**：每条关键信息附页面行号或 JSON 记录定位

## 输出格式

```markdown
## 回答

<综合答案>

## 引用来源
- [[xxx]] — <为什么相关>（概念页或文献页，按文件名自动解析）

## 开放问题
- [问题: ...] （如果有知识库中尚未覆盖的方面）
```

## 归档判断

如果这次查询产生了有长期价值的见解，在回答末尾提示用户：
"这次讨论是否归档到 brainstorming/sessions/？"

## 边界条件

- **查询无结果**：如实报告"知识库中未找到相关信息"，列出最接近的搜索词或相近主题供参考，不编造内容
- **查询歧义**：如果关键词可能指代多个概念（如"氧化"可能是热氧化/电化学氧化/等离子氧化），列出所有可能含义请用户澄清
- **index.md 缺失或损坏**：报告"全局索引不可用"，回退到直接搜索 `wiki/` 目录文件，建议运行 `/forge-health` 修复
- **仅部分匹配**：按相关度降序排列结果，明确标注每条匹配置信度（高/中/低），低置信度结果标记 `[间接相关]`
- **知识库范围外问题**：诚实告知"这超出了知识库覆盖范围"，可补充一般知识但标注 `[来自通用知识，非知识库内容]`

## 双链规范

所有 wiki 链接使用裸文件名（不带目录前缀的 `[[文件名]]`），由工具按文件名自动解析。唯一例外是项目页——因与同名概念页冲突，需加 `projects/` 路径前缀。

- `[[概念名]]` — 链接到 concepts/ 下的概念页面
- `[[文献标题]]` — 链接到 literature/ 下的文献页面
- `[[方法名]]` — 链接到 methods/ 下的方法页面
- `[[projects/项目名]]` — 链接到 projects/ 下的项目页面
- `[[index]]` — 回到全局索引
