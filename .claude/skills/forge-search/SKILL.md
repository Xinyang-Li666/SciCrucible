# /forge-search — 知识查询

> **SciCrucible 根目录**: `D:\科研\SciCrucible\` —— wiki/ 以此为基准。

用自然语言查询知识库，返回综合分析答案。

## 流程

1. **读索引**：先读 `D:\科研\SciCrucible\wiki\index.md` 了解知识库结构
2. **定位入口**：根据用户问题，找到最相关的概念/文献/方法页面
3. **遍历关联**：沿页面中的 `[[wiki-link]]` 扩展到相关页面
4. **综合回答**：基于找到的内容组织答案
5. **标注来源**：每条关键信息附 `[来源: 页面名]` 链接

## 输出格式

```markdown
## 回答

<综合答案>

## 引用来源
- [[xxx]] — <为什么相关>（概念页或文献页，按文件名自动解析）

## 开放问题
- [问题: ...] （如果有知识库中尚未覆盖的方面）
```

## 归档判断

如果这次查询产生了有长期价值的见解，在回答末尾提示用户：
"这次讨论是否归档到 brainstorming/sessions/？"

## 边界条件

- **查询无结果**：如实报告"知识库中未找到相关信息"，列出最接近的搜索词或相近主题供参考，不编造内容
- **查询歧义**：如果关键词可能指代多个概念（如"氧化"可能是热氧化/电化学氧化/等离子氧化），列出所有可能含义请用户澄清
- **index.md 缺失或损坏**：报告"全局索引不可用"，回退到直接搜索 `wiki/` 目录文件，建议运行 `/forge-health` 修复
- **仅部分匹配**：按相关度降序排列结果，明确标注每条匹配置信度（高/中/低），低置信度结果标记 `[间接相关]`
- **知识库范围外问题**：诚实告知"这超出了知识库覆盖范围"，可补充一般知识但标注 `[来自通用知识，非知识库内容]`

## 双链规范

所有 wiki 链接使用裸文件名（不带目录前缀的 `[[文件名]]`），由工具按文件名自动解析。唯一例外是项目页——因与同名概念页冲突，需加 `projects/` 路径前缀。

- `[[概念名]]` — 链接到 concepts/ 下的概念页面
- `[[文献标题]]` — 链接到 literature/ 下的文献页面
- `[[方法名]]` — 链接到 methods/ 下的方法页面
- `[[projects/项目名]]` — 链接到 projects/ 下的项目页面
- `[[index]]` — 回到全局索引
