# 建库模型复核分流规则 v2

**基本原则：证据清楚的候选不逐条送模型复审；模型重点处理存疑项。** 每条候选先做原文定位与程序检查，再按风险分流。模型不能代替缺失原文，也不能把模型的自信回答当证据。本规则用于新批次，不追改历史结果。

## 三类候选

| 类别 | 进入条件 | 模型复审与记录等级 |
|---|---|---|
| 清楚、低风险 | 原文表格/正文直接给出样品标签、性质原值及单位；处理和测试条件可唯一绑定；已报道的组成、误差和压痕方法均采入或如实标缺；来源逐字段定位；无图读、OCR 疑点、单位倍率、跨区域赋值、同名多事件、源内冲突或任务范围疑点；程序检查通过 | **不逐条送模型**。走现有 `local-first-risk-review/1.0` 的来源内确定性抽样：普通项 20% 向上取整、至少 2 条；样本支持且无阻塞时，未逐条复核者仅为 `partial/program_checked`，样本为 `sampled_supported`。一篇仅 1–2 条时抽样可能覆盖全部。 |
| 存疑、高风险 | 图点估读、OCR/符号、单位或倍率、跨页/表关联、同名样品多状态、组分名义/实测身份、源内冲突、样品与条件绑定等存在疑点；且原文材料足以让复核作出判断 | 先定向核原文/原图，补齐实际发送的证据包；仍需判断的字段逐条或按同篇共享证据打包送 **targeted** 模型复审。没有可判证据则暂缓，不靠重复问模型求通过。 |
| 暂缓/排除 | 关键条件缺失、请求缺目标样品/事件/时间点、证据包缺必要页、当前任务不需要的辅助数据，或原文明确不适用 | 暂缓者保留候选、证据、原因和重新进入条件；明确不适用者排除。两者都不送模型、不算 accepted 或全文完成。 |

即使被判为低风险，也要逐条核对原文数值、原单位、样品和状态绑定；“程序通过”不能证明未检查到的事实正确。当前 Al–Cu 主目标是同一样品/制备与峰时效起点后，在 200/250 °C 约 100 h 暴露、室温测试的 HV。峰态起点等必要前提可随目标处理；其他辅助数据默认暂缓，除非本批明确交付辅助库。已有通过的辅助记录不撤销。

## 按篇执行

1. **审计一次。** 冻结 PDF/文本指纹与任务范围，给每个候选写 `record_id/候选ID、风险类别、原文定位、程序检查、原因、重新进入条件`。先修正已知提取漏项；原文确未报告且科学 profile 允许为空时如实保留缺失，不要求模型猜。
2. **按协议分流。** 大规模收集的低风险免逐条复核，须用已有 `graded_collection` 准入协议和单独的发布授权；来源内抽样失败时只升级受影响实验范围。高风险的 `targeted` 请求仍须有充分证据、明确字段和发送额度。现有 `review-cycle` 严格模式继续用于要求 `strict/completed` 等级的记录；它不能把 `partial/program_checked` 映射成 strict accepted。
3. **发送前看实物。** 预览实际 pending payload，确认目标样品、事件、温度/时间、组分和测量方法的证据跨度在内；图读含原图、图例、轴及目标点。只发送 pending，held 不发送。共享证据在现有 bundle/字符限制内合并，不能合并掉每条记录的必需判断。
4. **复用与停止。** 来源、候选事实、请求签名、执行设置未变时复用原回答；变动时只重审受影响字段。模型返回 conflict/insufficient 时回源或隔离，不自动重问。正式 commit 仍单独授权。

## 质量等级与节约口径

`partial/program_checked` 表示“来源和程序检查完成，但该条未得到独立语义复核”，不能在主表中显示为严格复核通过。`sampled_supported` 与 `targeted_supported` 也须按原协议标明，不能隐去其区别。严格流程的 accepted 仍需该流程要求的 verify，strict 模式另需 blind_extract/coverage；两套流程不混用。

每篇记录候选总数、低风险/高风险/暂缓/排除数、抽样和 targeted 请求数、已知 tokens、实际耗时、各质量等级与失败升级数。先用小批次实测；**事后回放可避免的调用不等于净节约**，暂缓记录日后可能仍需复审。
