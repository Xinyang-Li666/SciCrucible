# 建库单篇增量审计

目标是减少重复读原文和重复验收。每篇只生成一次紧凑审计包；后续步骤按冻结指纹和变化字段复用它。发送前按 [模型复核分流规则](db-model-review-triage.md) 区分低风险、存疑与暂缓候选；低风险在已有分级收集协议中不逐条送模型，存疑项定向复核。不同复核等级必须清楚标注，不改变 strict 或正式入库门禁。

## 单篇一次审计包

在准备候选时，执行方于该篇新批次目录保存一份短表，主代理在发送前独立核对：

| 内容 | 最少记录 |
|---|---|
| 冻结来源 | 文献 ID、DOI、PDF/文本 SHA256、原文页码与行号或精确 text span |
| 目标范围 | 样品、处理分支、性质、目标条件、辅助/主目标分类、候选数 |
| 字段—证据覆盖 | 每个非空的组分元素、数值与原单位/误差、关键热史、测试方法分别指向原文；未报告字段明示未报告 |
| 来源分类 | 作者直接报告、图读/换算、数据库生成的 ID/状态/范围标签分开；生成标签不得标 `reported` |
| 源内差异 | 正文、表、图注的命名或数值差异逐项列出，注明是否影响目标；不能靠选一处默默消掉冲突 |
| 人工例外 | 仅列新字段、变更字段、缺证据、冲突、无法唯一关联、检查器未知错误及其处理结论 |

document-023 的桌面演练：Table 1/正文实测成分逐元素列出会发现 Zr 0.08 wt.% 遗漏；正文“Fig. 5(e) and 6(f)”与 Fig. 5 图注“(e) and (f)”并列可在发送前标出源内差异；`sample_id`、`state_id`、`series_id`、`auxiliary_only` 在来源分类栏应标为数据库生成，而非作者报告。以上是待执行核对规则，不声称已减少固定分钟数。

## 执行与独立验收

1. 新篇先核对目标范围与原文锚点，制作一次审计包。常规篇计划可引用已冻结领域计划的背景，只写本篇范围差异、允许文件、检查与停止条件，仍保存到 `docs/superpowers/plans/`。
2. `prepared`/`cycle`/授权/渲染存在时分别运行对应 `batch_check.py`。主代理记录源、prepared、cycle、授权和结果哈希；哈希不变且结论适用时复用已核对定位，只深读 changed、unverified、contradictory 字段。检查器失败、哈希变化或问题范围变化时重新核对相关部分。
3. 子代理产出后，主代理独立核对请求只含 pending、账本与授权一致、记录数和状态统计；有导出主表时，**程序化逐行**对照全部记录的 ID、组分、性质原值/单位、条件、状态、来源。人工看不一致项和覆盖不同样品/条件的少量抽样行，不对每行重复通读 PDF。
4. 原文仍不能确认、样品或条件有歧义、源内冲突影响结论时，读原文并隔离，不重复模型复核求通过。`conflict/insufficient` 不自动重问，`held` 不发送；正式入库仍走单独授权。

## 失效与回退

PDF/文本或证据跨度的指纹改变、候选新增性质/样品/条件、来源分类变更、原文图表与正文冲突超出既有审计包、旧包缺字段定位或核查结果无法复现时，该包对应部分失效；若无法圈定影响范围，回退整篇源审计。失败不能当作“无记录”或“已通过”。
