# /forge-ingest — 文献摄入

读取原始文献文本，编译成结构化 wiki 页面。

## 预检与证据优先（优先于下方旧流程说明）

Windows目录/单文件预检运行 `pwsh -File scripts/forge-ingest.ps1 -Source "<PDF或目录>" -Topic "<课题名>"`；不提供 `-Source` 时处理 `raw/new-papers/`。其他系统可运行 `bash scripts/forge-ingest.sh --topic "<课题名>"` 处理默认暂存区；指定来源时直接调用 `python scripts/ingest_prepare.py "<PDF或目录>" --topic "<课题名>"`。Python入口要求Python 3.11+及PyMuPDF或Poppler（pdfinfo、pdftotext）。不自动安装依赖。脚本只做预检和PDF文本准备，不生成wiki页面或移动文件。

1. 读取 `.kiro/.ingest_cache/manifest.json` 和 `report.md`。`ready`仅代表自动预检通过；`needs_review`须核实单页、稀疏文本、DOI候选与索引；`duplicate_sha256`跳过完全相同文件的重复编译，保留原文件；`error`记录原因后继续其他文献。单页可能是合法短文或SI，不能自动删除。扫描件需要OCR/视觉核验。
2. 从题名、作者、首页/正文页脚核实本文DOI；前三页DOI只是候选，出版社封面推荐文章和参考文献中的DOI不能当作本文。同DOI的正文、SI、首页和不同版本须关联而非盲目丢弃；优先使用完整正文。检查起止页、正文、参考文献与SI，不因页数>1就认定全文完整。
3. 缓存使用源文件SHA256命名，文本含 `<!-- PDF page N -->`，JSON逐页保留空页；N为物理PDF页序号，不等同印刷页码。原文不变可复用缓存，坏缓存重建，失败项下次重试。默认保留缓存供追溯，不执行旧的全量清理步骤。
4. 课题从用户指定、`wiki/`已有课题和项目目录综合判断；允许新建课题。用户指定的课题名作为首选落点；没有指定时再结合文献内容匹配已有课题，不能仅因不匹配示例就归入“其他”。课题专属内容写入 `wiki/<课题名>/{literature,concepts,methods,projects}/`，跨课题方法放 `wiki/通用/methods/`。例如SiNx薄膜任务可以使用 `wiki/SiNx薄膜生长/`，该示例不构成默认分类。
5. 编译遵循 `references/evidence.md`：先逐篇笔记及来源定位，再综合概念/方法页，最后更新索引。若项目配置或用户要求了专项提取规范，同时遵循该规范；专项字段只用于指定项目，不强制所有材料论文填写。未知值写“未报道/未核实”。MP2不是DFT，经典MD不是AIMD，DFT训练势不是逐步DFT；区分气相、晶面、非晶表面、实验和跨体系类比。
   - 对项目型批次，先检查用户指定的项目目录或匹配课题下 `notes/ingest-profile.json`；存在时读取其 `extraction_reference`，按 `source_dir`、`topic`、批次大小和源文件策略处理。相对路径从SciCrucible根目录解析。配置缺失、无效或与用户指令冲突时，以用户指令为准并回退通用模板；不能把配置中的建议当作PDF已完成科学核验。
6. 每篇笔记核验完成后才更新索引/BibTeX；源PDF默认保留原路径，只有用户指定归档时才移动。中断时保留源PDF，重跑先核对已有页面。DOI不区分大小写，保留现有索引字段；新条目增加 `path`（wiki相对路径）、`source_sha256`、`source_pdf`、`evidence_status`。写索引前重新读取，先写临时文件再替换；损坏时先保留原副本再重建。BibTeX按已核实DOI去重。
7. 不覆盖已有页面或归档PDF；目标已存在时比较SHA256，相同则复用，不同则保留版本。不能因提取成功而移动文件。成功状态由编译者逐篇核验后记录，预检脚本不推断成功。

下方“运行脚本”统一使用上述入口；脚本只负责预检及提取，wiki编译仍由执行本技能的助手完成。`--extract-questions`是技能层可选参数，不传给预检脚本。

> **SciCrucible 根目录**: `D:\科研\SciCrucible\` —— 所有 wiki/、raw/、scripts/ 路径以此为基准。

## 输入

- **无参数**：预检 `D:\科研\SciCrucible\raw\new-papers\` 中的 PDF；后续由执行助手逐篇核验并编译
- **有参数**：指定文本文件路径或 PDF 路径（兼容单文件模式）

## 批量流程（无参数模式）

1. **运行脚本**：Windows运行 `pwsh -File scripts/forge-ingest.ps1 -Topic "<课题名>"`；其他系统运行 `bash scripts/forge-ingest.sh --topic "<课题名>"`，预检并提取默认 `raw/new-papers/`。若文献已位于 `raw/papers/<课题>/` 或其他目录，显式提供 `-Source`（PowerShell）或调用 `ingest_prepare.py <PDF或目录> --topic "<课题名>"`。
2. **逐篇处理**：对每个提取的文本文件，执行以下步骤：
   - **识别元数据**：提取标题、作者、年份、期刊、DOI
   - **评估期刊质量**：对照 `journal-ratings.xlsx` 查询期刊评级（评级 1-4，1 为最高；含"顶级"标识）
   - **生成文献页面**：写入 `wiki/<课题>/literature/<短标题>.md`；课题使用用户指定值，或按内容匹配已有/新建专题，不限于少数示例。在页面中标注评级信息
   - **提取新概念**：识别论文中引入或讨论的材料科学概念，按中颗粒度原则决定：
     - 是否可归入已有概念页（如新的掺杂元素 → 更新 [[掺杂策略与设计原理]]）
     - 是否需要新建概念页（涉及全新物理机制且无法归入已有页面）
     - **落点分层**：课题专属概念写 `wiki/<课题>/concepts/`；跨课题通用概念（掺杂/热力学/氧化理论等，UHTC↔正极共用）写 `wiki/通用/concepts/`
     - 新建概念页时在 index.md 的对应专题组下添加条目
3. **统一收尾**：
   - 更新 `wiki/index.md`：
     - 在对应年份下添加文献条目
     - 如有新概念页，在对应专题组下添加条目
     - **绝不留下 `[待建立]` 标记**
   - **增量更新文献索引缓存** (`wiki/literature_index.json`)：
     - 如果文件不存在 → 从 `wiki/**/literature/*.md` 递归全量重建（覆盖所有课题子目录）
     - 如果文件存在 → 追加新摄入文献条目：
       ```json
       {
         "10.1016/j.actamat.2025.119123": {
           "title_normalized": "<标题归一化：小写+去标点+去多余空格>",
           "file": "<当前文件名>.md",
           "ingested": "YYYY-MM-DD"
         }
       }
       ```
     - 更新 `"updated"` 和 `"count"` 字段
     - **索引重建逻辑（首次运行或索引损坏时）**：
       - 递归遍历 `wiki/**/literature/*.md`（各课题 literature 子目录）
       - 提取 DOI: 匹配 `**DOI:**\s*([^\s\n]+)`
       - 提取标题: 匹配 `^#\s+(.+)$`
       - 标题归一化: 小写 + 去标点 + 去多余空格
       - 文件名: 当前文件名
       - 摄入日期: 从文件修改时间或 `[新增: YYYY-MM-DD]` 标记推断
     - **注意**：文献页无 YAML frontmatter——DOI 是 `**DOI:** value` 格式，标题是 `# Title` 格式
   - 更新 `D:\科研\SciCrucible\raw\references.bib`，追加 BibTeX 条目
   - **源PDF处理**：默认保留原路径。只有用户明确要求归档/移动时才执行移动，并在移动前核对目标路径和同名文件；预检或编译成功本身不构成移动授权。
4. **保留缓存**：默认保留逐页文本、JSON及预检清单供追溯，仅在用户要求时清理

## 单文件流程（有参数模式，兼容旧行为）

1. 指定PDF或目录时，先经 `scripts/forge-ingest.ps1 -Source <PDF或目录> -Topic <课题名>` 预检与提取；文本文件可直接读取并标注来源。
2. 按单篇流程生成wiki页面，完成正文、元数据及证据核验后更新索引。
3. 默认保留PDF原路径；用户指定归档时才移动，并记录新旧路径。

## 文献页面格式

摄入每篇文献时，**首先判定文章类型**（纯实验/纯计算/实验+计算），然后按 `references/template.md` 中的完整模板生成文献笔记页面。

模板包含：文章类型判定规则、完整 Markdown 模板（研究概述→组分-条件-性质-机制→关键发现→方法→与我的工作关联→相关文献）、撰写质量要求。

## 概念页创建（中颗粒度）

识别到新概念时，按以下优先级处理：

1. **归入已有页面**（首选）：如果新概念属于已有概念页的主题范围，在该页面中增加 `###` 子标题段落
2. **新建专题页**：如果涉及全新物理机制且无法归入已有页面，创建新概念页
3. **判断依据**：
   - 共享同一物理机制/设计原理 → 合并
   - 涉及完全不同的物理框架 → 独立
   - 一个概念被 5+ 其他页面独立引用 → 独立

新建概念页后，必须同步更新：
- index.md 对应专题组
- 相关枢纽页的阅读导航表
- 所有引用该概念的已有页面中的 [[双链]]

## 方法页触发创建（中颗粒度）

### 方法页格式

```markdown
# <方法名>

> <一句话定义——这个方法做什么、基于什么原理>

## 基本原理

- <核心物理/化学原理>
- <关键方程或判据>

## 实验流程（合成/表征方法）

1. <步骤1>
2. <步骤2>
...

## 关键参数

| 参数 | 推荐范围 | 影响 |
|------|---------|------|
| <参数> | <值> | <对结果的影响> |

## 变体与适用范围

### 变体1：<名称>
- <特定条件下的变体或替代方案>

### 变体2：<名称>
...

## 关联

- [[相关概念页]]
- [[使用此方法的文献]]
- [[相关方法页]]
```

### 触发条件

摄入新文献后，扫描其「方法」段落中的每个方法。对照上述分组表：
- 如果方法名**不在**已有方法页的涵盖范围内→创建新的方法页
- 如果属于已有方法页的涵盖范围但该变体**尚未在页面中提及**→在该方法页中追加 `###` 子标题
- 方法页初始状态可以简略（基本定义+本文献中的使用方式），后续摄入其他使用同一方法的文献时增量补充

## 博士论文专项处理

博士论文（含硕士论文）体量大（100+ 页、5-8 章、100-200+ 参考文献），摄入时需**章节级系统提取**，不可仅做摘要级总结。

### 论文 Ch1 绪论的独特价值

博士论文 Ch1 绪论是经过高度组织的**领域微型综述**（引用 100-200+ 篇文献），其价值不亚于期刊综述论文。摄入时必须：

1. **提取发展脉络**：按时间线整理关键里程碑 → 充实相关概念页的历史背景
2. **提取机理模型**：Ch1 通常会以结构化方式呈现领域内的经典模型（如三层氧化截面、温度分区氧化模型）→ 这些是概念页的最佳增量
3. **提取方法对比**：Ch1 的方法综述（制备工艺、表征手段）→ 可充实 methods/ 页面
4. **标注"来源: XX论文Ch1"**：在概念页中区分原始研究发现（实验章节）与论文综述内容（Ch1），避免将综述观点误归为论文原创

### 实验章节的层级提取

每章按以下层级提取：
- **定量数据**：烧蚀率、力学性能、热导率等具体数值 → 可用于构建对比表
- **机制解释**：论文提出的物理/化学机制 → 评估可否提炼为新概念页
- **方法细节**：制备参数、表征条件 → 丰富 methods/ 或项目页的技术路线
- **组分-性能关系**：不同成分的性能对比 → 项目页的核心增量

### 论文间交叉关联

同一课题组/同一方向的多篇论文摄入后，应主动建立交叉关联：
- 对比不同论文的设计逻辑（如论文A的"骨架-填充" vs 论文B的"共晶自愈合"）
- 识别互补关系（块体陶瓷 vs C/C 复合材料改性）
- 合并提炼为共享的理论框架（如"优先氧化与多相协同"统一了两篇论文的机制）

## 项目页更新触发

摄入新文献后，检查是否触发项目页更新：
- 新文献填补了某项目的知识空白 → 更新项目页 §2 文献脉络
- 新文献提供了新的机制理解 → 更新项目页 §5 核心发现
- 新文献开启了新的研究方向 → 更新项目页 §7 开放问题

项目页更新保持增量：在对应章节追加新内容，标注 `[新增: YYYY-MM-DD]`。

## 开放问题提取（`--extract-questions` 可选参数）

当用户传入 `--extract-questions` 时，在摄入完成后执行以下额外步骤：

### Step 1 — 识别候选段落

检查文献 PDF 提取文本中是否包含以下段落标题（英文和中文变体）：
- "Future Work" / "Future Directions" / "Outlook" / "Open Questions"
- "Discussion" / "讨论" 中的局限性段落（"limitation", "caveat", "不足", "局限"）
- "Conclusion" / "结论" 中的展望段落（"further", "remain", "warrant", "有待", "进一步"）

### Step 2 — LLM 提取结构化问题

如果存在候选段落，截取相关文本（前 2000 字），用 LLM 提取 1-3 个开放问题：

```
输入：PDF 文本中 Discussion/Future Work/Conclusion 相关段落
输出：每个开放问题包含：
  - 问题描述（一句话，可被引用的陈述）
  - 当前研究状态（为什么还没解决——技术瓶颈/认知缺口/实验困难）
  - 与本项目的相关性（直接相关/启发参考/远期方向）
  - 来源标注（文献 [[链接]] 的哪个段落）
```

### Step 3 — 写入项目页

将提取的问题写入对应项目页的 §7「开放问题」章节：

```markdown
### OQ-2026-07-06-1 | <问题简述>

- **来源**: [[AuthorYear-Keyword]] (§Discussion/Future Work)
- **问题**: <一句话描述>
- **现状**: <为什么还没解决>
- **相关性**: <与本项目的关系>
```

**注意**：
- 开放问题提取是**可选步骤**，不在 `/forge-ingest` 主流程中自动执行
- 仅在用户显式传入 `--extract-questions` 时启用
- 如果论文没有明确的未来展望段落，如实报告「未找到可提取的开放问题」
- 提取的问题需要用户审阅确认后才写入项目页

### Step 4 — 写入 weekly.yaml 反馈（可选）

如果是 `/forge-weekly` 触发的自动摄入，额外记录：
- 该文献属于哪个课题的关键词检索结果
- 是否被摄入（用于计算关键词摄入率）
- 追加到 `weekly.yaml` 的 `feedback` 字段

## 输出

## 边界条件

- 如果默认 `new-papers/` 为空，提示用户指定已归档PDF目录或提供文件
- 如果某篇 PDF 文本提取失败（空或乱码），跳过该篇，保留在原路径并继续处理下一篇
- 如果论文与已有文献高度重叠，侧重补充差异点而非重复摘要
- 绝不覆盖已有的文献页面，只做增量补充
- 如果一篇论文涉及多个概念，确保每个概念页面都被更新
- 低评级期刊（评级3/评级4）仍正常摄入和创建页面，但在项目页文献脉络中不予引用（除非是领域内无可替代的基石文献）
